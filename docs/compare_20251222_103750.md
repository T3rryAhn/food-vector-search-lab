# 실험 결과 및 분석 (Local Embedding 기반 검색)

## 1. 실험 목적

본 실험의 목적은 다음과 같다.

- 음식 DB(`food_data.csv`)를 대상으로  
  **자연어 의도 기반 검색이 로컬 임베딩 모델에서도 어느 수준까지 가능한지** 확인
- 단순 벡터 검색의 한계를  
  **쿼리 확장(Query Expansion)**, **카테고리 가드레일**, **결과 다양화(Diversification)** 로 얼마나 보완할 수 있는지 검증
- 실제 서비스(EATIT) 적용 전,  
  *“이 방식으로 어디까지 커버 가능하고, 어디서 한계가 명확해지는지”*를 정리

---

## 2. 실험 구성 요약

### 2.1 사용 데이터
- `food_data.csv`
- 주요 컬럼
  - `food_name`
  - `cat_large`, `cat_mid`
  - 영양소 정보 (kcal, protein_g, sugar_g, sodium_mg 등)

### 2.2 사용 모델
- **Snowflake Arctic Embed L v2**
- **Jina Embeddings v3**

### 2.3 검색 파이프라인
```
[Query]
↓
(선택) Query Expansion
↓
Vector Search (FAISS, Top-N)
↓
Category Guardrails (score 조정)
↓
Diversification (중복/도배 방지)
↓
Top-K 결과
```

## 3. 주요 실험 결과 요약

### 3.1 “따뜻한 국물” (food)

- ❌ 초기 문제  
  - `HOT 차`, `라떼` 등 **음료 계열이 상위 도배**
- ✅ 개선 후
  - `국`, `탕`, `찌개`, `전골` 중심 결과 도출
  - Snowflake / Jina 모두 **식사류로 안정 수렴**

**결론**  
> 온도 표현(따뜻한/뜨끈한)은 음료 쪽 임베딩을 과도하게 끌어당김 →  
> 국물 키워드 확장 + food 가드레일 조합이 필수

---

### 3.2 “뜨끈한 한 끼” (food)

- Snowflake
  - 여전히 HOT 음료 상위 노출
- Jina
  - 식사/국물/밥류 혼합 결과

**해석**
- “한 끼”는 **텍스트 임베딩만으로는 식사 개념이 약함**
- 이 케이스는 **쿼리 확장만으로 한계 명확**
- → *서비스 단계에서는 “식사 여부”를 명시적으로 받는 설계가 필요*

---

### 3.3 점심 / 혼밥 / 일반 식사 쿼리

- “회사 점심으로 부담 없는 음식”
- “혼밥으로 간단한 메뉴”

**결과**
- 양 모델 모두:
  - 볶음밥, 국밥, 잡채, 김밥 등 **의도에 부합**
  - 동일 카테고리 도배는 다양화로 완화

**결론**
> *일상 식사 쿼리*는  
> **Local embedding + 얕은 규칙 보강만으로도 실사용 가능 수준**

---

### 3.4 영양소 의도 쿼리

- “운동 후 단백질 많은 음식”
- “단백질 높고 당류 낮은 음식”
- “나트륨 낮은 식단”

**공통 결과**
- 텍스트 검색 기준:
  - 단백질/저당/저나트륨이 *명확히 반영되지는 않음*
- 일부 고단백 음식이 나오긴 하나 **일관성 부족**

**결론**
> 영양소 조건은  
> **텍스트 검색의 책임이 아니라, reranking(hybrid) 영역**

---

### 3.5 간식 / 디저트 / 음료 분기

- `kind = food / drink / snack` 강제 분기 후
- 가드레일 적용 결과

**성과**
- snack → 빵/아이스크림 중심
- drink → 음료로 안정 수렴
- food → 음료 유입 대폭 감소

**중요 인사이트**
> *카테고리 선택은 검색 정확도 문제가 아니라 UX 설계 문제*  
> 프론트에서 반드시 택일하도록 하는 것이 가장 효과적

---

## 4. 드러난 한계점

### 4.1 벡터 검색의 구조적 한계

- 임베딩 공간에는 **“카테고리 필터” 개념이 없음**
- 모든 아이템이 하나의 벡터 공간에 섞여 있음
- 결과적으로:
  - “뜨끈함” → HOT 음료
  - “달달” → 달걀/달래 같은 표면 토큰 오인

### 4.2 규칙은 ‘완화’이지 ‘해결’은 아님

- 가드레일 / 감점 / 다양화는
  - ❌ 잘못된 후보를 제거
  - ✅ 하지만 **올바른 후보를 새로 만들어주지는 않음**

---

## 5. 현재 단계 결론 (A안 평가)

### A안: Local Embedding + 규칙 보강

**장점**
- 구현 단순
- 로컬 실험/디버깅 용이
- 의도 검색의 큰 흐름 검증 가능

**한계**
- 카테고리 혼합 문제의 근본 해결 불가
- 영양소 의도는 텍스트 검색만으로 불충분
- 검색 공간을 “의도별로 나누는 구조” 부재
