# Experiment Log

## 1. 실험 목적
음식 DB 벡터 검색 실험을 통해,
- 짧고 추상적인 사용자 쿼리(예: “야식”, “시원한 음료”)에 대해
- 임베딩 모델이 어떤 방식으로 후보를 검색하는지 확인하고
- 실제 추천 관점에서 발생하는 문제점을 파악한다.

본 실험은 Snowflake Arctic Embed v2.0과 Jina Embeddings v3를 대상으로 진행했다.

---

## 2. 관찰된 문제점

### 2.1 짧은 쿼리에서의 의미 붕괴
- “야식” 쿼리에서 `밤식빵` 등 ‘밤(栗)’ 재료가 포함된 빵류가 상위에 노출됨
- “차가운 디저트 / 시원한 음료” 쿼리에서 `냉이나물` 등 의미적으로 무관한 항목 등장

→ 짧은 단어 쿼리에서 모델이 **의미가 아닌 표면 단어/형태소 유사성**에 과도하게 반응하는 현상 확인

### 2.2 결과 쏠림 현상
- 특정 음식(예: 콩나물)이 Top-K 결과에 반복적으로 등장
- 추천 결과가 다양하지 않고 “도배된 느낌”을 주는 문제 발생

---

## 3. 개선 방향

### 3.1 쿼리 확장 (Query Expansion)
사용자가 입력한 짧은 쿼리를 내부적으로 의미가 풍부한 문장으로 확장하여,
모델이 단어 수준이 아닌 **의도 수준**에서 검색하도록 유도한다.

예:
- “야식” → “늦은 밤에 먹는 간단한 음식 부담 없는 야식 간식”
- “시원한 음료” → “차가운 아이스 음료 시원한 음료 여름”

### 3.2 결과 다양화 후처리 (Diversification)
Top-K 검색 결과에 대해,
- 동일 토큰(예: 음식명 핵심 단어)
- 동일 중분류(cat_mid)

가 과도하게 반복되지 않도록 제한하여,
추천 결과의 체감 품질과 신뢰도를 개선한다.
