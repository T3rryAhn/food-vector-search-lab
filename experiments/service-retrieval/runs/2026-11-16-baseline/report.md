# 2026-11-16 — 서비스 검색 품질 기준선

## 출발점

사용자가 '메뉴를 골라 먹고 싶은데 계란 같은 단품이 나온다'고 지적했다. 기존 배포 검증은 HTTP/화면/속도 중심이었고 메뉴 적합성 검증이 부족했다. 빠른 응답과 좋은 추천을 분리해 평가하기 시작했다.

## 방법

작성한12개 검색어, 상위6개씩72개 결과. 운영 중인 모델의 내부 추천 경로에 순차 요청했고 커뮤니티 집계는 변경하지 않았다. 지연은 웜 모델 로컬HTTP 기준이며 중앙값0.1675초, 범위0.159~0.202초. 부하 시험/다수 사용자 평가는 아니다. 원본은 results.json, provenance는 manifest.json.

## 관측

| 입력 | 관측한 결과 | 에이전트의 주관 평가 |
|---|---|---|
| 간단한 점심 한 끼 | 리조또, 노른자, 달걀말이, 적어조림, 삶은 달걀, 흰자 | 한 끼·반찬·부위 혼재, 미흡 |
| 운동 후 단백질 많은 한 끼 | 리조또2종, 노른자, 흰자, 송편, 절편 | 고단백 조건을 영양 수치로 검증하지 못함 |
| 따뜻한 국물 | 전골, 떡국, 찌개, 라면 국물 | 대체로 관련 있지만 국물만인 부분 식품 포함 |
| 차가운 면 요리 | 용기라면, 소고기국, 칼국수, 수제비 등 | 명확한 차가운 면 메뉴0/6 |
| 맵지 않은 저녁 메뉴 | 매콤 밀푀유나베, 노른자 등 | 명백한 조건 위반 |
| 짜지 않은 국물 요리 | 라면 국물, 노른자 등 | 국물 아닌 결과; 저염 충족 여부는 미검증 |
| 김치볶음밥 | 소고기볶음밥, 김밥, 어묵볶음 등 | 해당 메뉴0/6.원본 데이터에는 관련15행 존재 |
| 고기 없는 채소 위주 한 끼 | 닭죽, 어육소시지전, 오야꼬동 소스 등 | 제외 조건과 메뉴 자격 모두 미흡 |
| 매콤한 면 + 면 카테고리 | 매운돈코츠라멘, 비빔면, 탄탄면 등 | 카테고리6/6 일치, 비교적 양호 |
| 시원한 음료 | HOT 음료2개, 빙수2개 포함 | 온도·종류 조건 혼재 |
| 달콤한 디저트 | 케이크·아이스크림 위주, 첫 결과 소세지빵 | 비교적 양호하나 첫 결과 약함 |
| 차가운 담백한 가벼운 부드러운 | 스무디, 빙수, 달걀 부위 | 취향 선택만으로 메뉴를 고르기 어려움 |

평가 기준은 '지금 먹을 음식 하나를 고르는 데 도움이 되는가'다. 음식명/분류로 판단했으며 전체 조리법·성분을 검증하지 않았다. 정확도 백분율이나 채식/영양 안전성을 주장하지 않는다.

## 코드로 확인한 사실

- 의도 판정에서 '차' 부분 문자열이 '차가운'에도 매칭된다. '음료' 자체는 의도 판정 키워드에 없다.
- '짜지 않은'에 짠맛 확장 규칙이 적용된다. 부정 표현을 명시적으로 처리하지 않는다.
- 완성 메뉴/반찬/식재료/부위/소스 구분이 없다.
- 감점 재정렬 전에 후보를 k*3개에서 중단한다. 다양화 fallback은 남은 후보로 결과 수를 채운다.
- 캐시된 모델 query prompt는 'query: '인데 실제 코드는 다른 영어 지시문을 붙인다. 성능 영향은 아직 A/B 미측정.
- 로컬 CSV/메타는14584행, 코드 순서 일치. 빵·과자5982행과 음료3871행으로 약67.6%. 분포가 결과에 미치는 인과는 미측정.
- 저장 메타 태그와 현재 indexer 생성 규칙이 일부 달라 인덱스 생성 계보를 확인해야 한다. 벡터 자체의 오류가 입증된 것은 아니다.

## 판단

첫 개선을 큰 모델 교체로 시작하지 않는다. 메뉴 자격, 부정/의도 처리, 입력 프롬프트 및 음식명 검색을 먼저 분리해 검증한다. 과거 연구의 가드레일 판단도 제품 목적에 맞춰 재검토한다. 현재는 **문제 재현과 가설 수립 완료**이며 개선 전후 성과는 아직 없다.
