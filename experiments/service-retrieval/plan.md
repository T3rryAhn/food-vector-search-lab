## 실험 전에 필요한 것

1. 별도 실행 환경과 운영 기준선 구현을 고정한다. 기존 Lab CLI 결과를 대신 기준선이라 부르지 않는다.
2. 운영 인덱스의 생성 코드/모델 revision/메타 정합성을 확인한다. 확인 전 자동 재생성하지 않는다.
3. 지금12건은 탐색셋이다. 수정에 직접 사용하지 않은 표현/예외 쿼리를 별도 holdout으로 만든다.
4. 메뉴/반찬/단품의 경계와 주관 판정 기준을 먼저 적는다. 근거가 없으면 '판정 불가'를 허용한다.

## 기록할 지표

- 부적격 식품 노출률@6: 부위/소스 등 제품 기준 위반 결과 ÷ 실제 반환 결과. 결과가 없으면 별도 표시.
- 명시적 조건 위반률: 검증 가능한 조건만 분모에 포함; 영양/채식의 미확인을 정답으로 세지 않는다.
- 정확 음식명 검색의 Hit@6와 첫 관련 결과 위치. 관련 음식군 판정 기준 고정.
- 메뉴군 중복, 반환 개수, 빈 결과율: 적게 반환해 노출률만 좋아지는 것 방지.
- 주관 적합성: 0 부적합 / 1 부분 적합 / 2 선택 후보로 적절, 이유 기록. 원본 이름/영양 연결 보존.
- 동일 환경의 웜 요청 지연. 반복·표본 수를 함께 기록하며 부하 성능으로 일반화하지 않는다.

채택은 이름 검색/조건 위반의 개선과 기존 양호한 국물·디저트 사례의 회귀 여부를 함께 보고 판단한다. 여러 수정이 필요하면 단일 변수 비교 뒤 조합 실험을 따로 남긴다. 구현 실패·기각 결과도 보존한다.

## 이후 UI 작업

메뉴 구분과 검색 수정의 평가 후, 입력→문장 임베딩→미리 계산한 음식 벡터와 비교→조건 필터→카드 흐름을 설명 애니메이션으로 보여준다. 실제 서버 단계별 진행률을 계측하지 않는 동안은 진행률인 것처럼 연출하지 않는다. 유사도는 정답률이 아니다. reduced-motion과 키보드 사용을 지원한다.
